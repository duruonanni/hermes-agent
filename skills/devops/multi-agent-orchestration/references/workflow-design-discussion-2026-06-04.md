# 规范设计双阶段讨论模式（2026-06-04）

## 场景

用户需要建立一套「源码修改标准工作规范」，涉及：
1. 规范应该包含什么内容（文件分类、工作流模板、验证门禁、回滚方案）
2. 规范以什么形式落地（AGENTS.md / Skill / pre-commit hook / 全上）

## 关键发现

### 规范设计天然需要两轮

```
Round 1: 定方案内容
   用户输入 → 委派研究员(MiMo)搜社区实践 + 军师(DS Pro)出草案
   → 我综合 → 展示给用户

用户说「方案可以 但落地形式我不太懂」

Round 2: 评估落地形式
   用户输入 → 委派研究员(MiMo)查社区案例 + 军师(DS Pro)做评分表
   → 我综合推荐 → 用户决策
```

**绝不能自动推进 Round 2。** 用户说「方案可以」不代表他们想讨论实施。

### 评分表比单一答案更有效

军师推荐的 5 维评分表（强制力 / Token 开销 / 维护成本 / 发现成本 / 综合推荐度）在阶段二被用户接受度很高。原因是：
- 用户可以自己看分数，不用完全信任我的判断
- 每个选项都有明确理由，「不推荐」也有解释
- 渐进式路径（B→C→A）让用户选择介入深度，而不是全有或全无

### 社区调研 vs 架构分析的互补性

| 维度 | 研究员（MiMo, web 工具集） | 军师（DS Pro, _no_tools） |
|------|---------------------------|---------------------------|
| 输入 | 约 280K token（含 web_search 结果） | 约 12K token（纯摘要） |
| 输出 | 5.1K token | 3.9K token |
| 价值 | 社区真实案例、用户评价、GitHub Issues | 结构化评分表、工作流模板、分类体系 |
| 弱项 | 耗 token 多，可能搜到无关结果 | 无社区知识，可能漏掉实际使用反馈 |
| 结论 | 知道「社区在用 CLAUDE.md」 | 知道「AGENTS.md 比 Skill 强制力低」 |

两者在「规范设计」场景下是完美互补的——研究员告诉你真实世界怎么做的，军师告诉你应该怎么做。

## 渐进式推荐模式（B→C→A）

```
现在（零成本）→ 保持 B（AGENTS.md），写好行为规范和验证门禁
  ↓
本周内       → 加 C（pre-commit hook）—— 语法检查 + 遗漏提交提醒
  ↓
以后有需要   → 加 A（Skill）—— 详细的流程模板，按需加载
```

这种推荐模式的关键原则：
1. **最低成本起步** — 已经运行的 B 是零成本，不用动
2. **下一步有明确价值** — C 是最值得加的，因为它在 git commit 时强制执行
3. **预留升级空间** — A 作为可选，不强制
4. **每层有明确的「为什么现在不做」理由** — 避免用户产生焦虑
